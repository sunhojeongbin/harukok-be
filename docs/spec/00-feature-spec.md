# 🚀 MVP v1 기능 명세서 (재정의)

## 0. 이 문서의 목적

출시를 막고 있는 것은 기능 부족이 아니라 **범위가 고정되지 않은 것**이다. 이 문서는 기능을 늘리기 위한 문서가 아니라, **무엇을 안 만들지 확정하기 위한 문서**다.

- 기존 `MVP 기능 명세서`는 보존용으로 그대로 둔다. 개발 기준은 이 문서다.

---

## 1. 서비스 정의

하루콕은 **메모지** 형식의 일정을 체크하는 **투두 앱**이다.

- **대상**: 복잡한 생산성 앱 설정에 지친 사용자
- **사용 시점**: 아침에 오늘 할 일을 적고, 하루 동안 체크
- **해결**: 날짜 하나, 목록 하나. 설정할 것이 없음

이 정의에 들어맞지 않는 기능 요청은 전부 `다음 버전` DB로 보낸다.

---

## 2. 목표 출시일

- **목표 출시일: `2026년 11월 30일`**
- 날짜가 범위를 결정한다. 범위가 날짜를 결정하지 않는다.
- 날짜를 못 지킬 것 같으면 기능을 뺀다. 날짜를 미루지 않는다.

---

## 3. 원칙 (수치 상한)

- 화면 **7개 이하** (현재 5개)
- 기능 행 **25개 이하**
- 행당 명세 **5줄 이하**
- 명세서 작성 **1일 이내**
- 우선순위 3단계(높음/보통/낮음) 사용 금지 — 결국 전부 만들게 된다. **MVP 포함 여부 하나만** 쓴다.

---

## 4. 화면 목록 (5개)

1. **스플래시** — 자동 로그인 판정, 강제 업데이트 체크
2. **로그인** — 소셜 로그인, 약관 동의
3. **홈** — 날짜 이동, 할 일 목록, 완료 체크 (앱의 전부)
4. **할 일 작성** — 등록 / 수정 / 삭제 (바텀시트 권장)
5. **설정** — 로그아웃, 회원탈퇴, 약관, 버전

화면이 6개째 생기려 하면 그 기능은 MVP가 아니다.

---

## 5. 안 만들 것 (Out of scope)

아래는 **v1에서 만들지 않는다.** 상세 사유는 `다음 버전` DB 참고.

- 카테고리 / 태그
- 반복 · 루틴
- 검색
- 통계 · 대시보드
- 푸시 알림
- 공유 · 친구 · 크루
- 위젯 · 다크모드
- 드래그 순서 변경
- 공지사항

---

## 6. 개발 없이 때우는 항목

출시에 필요하다고 해서 전부 개발해야 하는 것은 아니다.

- **이용약관 / 개인정보 처리방침** → 노션 공개 페이지를 WebView로 띄움
- **문의하기** → `mailto:` 링크 또는 구글 폼
- **공지사항** → 만들지 않음. 강제 업데이트로 대체
- **오픈소스 라이선스** → 라이브러리 자동 생성 (Flutter `oss_licenses` 등)
- **강제 업데이트** → Firebase Remote Config 값과 앱 버전 비교

---

## 7. 운영 규칙

- **개발 시작 후 이 문서를 수정하지 않는다.** 수정하기 시작하면 범위가 다시 늘어난다.
- 새로 떠오른 기능은 예외 없이 `다음 버전` DB로 보낸다. 지우지 않는다 — 지우면 같은 논의를 다시 하게 된다.
- `기능 명세서` 행은 **담당자와 완료 조건이 비어 있으면 착수하지 않는다.**
- `출시 체크리스트`는 기능이 아니다. 개발이 끝나도 이게 안 끝나면 출시가 안 된다.

---

## 8. 진행 순서

- **1일차 오전** — 서비스 정의 확정, 출시일 확정, 안 만들 것 확정
- **1일차 오후** — 화면별 기능 행 작성, 완료 조건 기입
- **2일차** — 출시 체크리스트 담당·일정 배정
- **3일차\~** — 개발 시작 (이 문서는 더 이상 열지 않는다)
